Observability tells you if your system is working, but evaluations tell you if your agents are working *well*. In production, you need evaluations that run automatically (on a schedule or as part of a CI/CD pipeline), not manually from a notebook.

In this module, you'll import and run an evaluation pipeline in Red Hat OpenShift AI, then view the automated evaluation results in MLflow.

TIP: In this module, you're wearing **both hats**: AI Developers define the evaluation logic, while SRE/Platform Engineers manage the pipeline infrastructure and scheduling.

== Learning objectives

By the end of this module, you'll be able to:

* Import an evaluation pipeline definition into OpenShift AI
* Run an automated evaluation pipeline and configure its parameters
* View automated evaluation results in MLflow

== Why automated evaluations matter

Running evaluations manually from a notebook works during development, but it has limitations:

* **Manual**: Someone has to open the notebook and click Run
* **Not reproducible**: Results depend on the notebook environment and who ran it
* **Not schedulable**: You can't trigger it automatically on a model update or prompt change

AI Pipelines solve these problems by packaging evaluation logic into containerized steps that run on the OpenShift AI platform.

[cols="1,1",options="header"]
|===
|Inner Loop |Outer Loop

|Jupyter notebook
|AI Pipeline (Kubeflow Pipelines)

|Manual execution
|Automated, scheduled, or triggered

|Developer's workbench
|Platform-managed containers

|Interactive exploration
|Reproducible, auditable runs
|===

Red Hat OpenShift AI includes https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/{rhoai_version}/[Data Science Pipelines^] (based on Kubeflow Pipelines) for orchestrating multi-step ML workflows, including evaluation pipelines.

== Exercise 1: Import an evaluation pipeline

The mortgage-ai project includes a pre-compiled evaluation pipeline that packages a simple evaluation into 4 automated steps.

. In Red Hat OpenShift AI, navigate to **Develop & Train** > **Pipelines** > **Pipeline definitions**:
+
image::eval16.png[OpenShift AI Pipeline definitions page showing no pipelines with Import pipeline button,link=self,width=700]

. Click **Import pipeline** and configure it:
+
--
* **Pipeline name**: `eval-simple-run`
* Select **Import by url**
* Paste the pipeline URL:
+
[source,text]
----
https://raw.githubusercontent.com/rh-ai-quickstart/multi-agent-loan-origination/refs/heads/main/evaluations/pipelines_gen/simple-eval-pipeline.yaml
----
--
+
image::eval17.png[Import pipeline dialog with name eval-simple-run and Import by url selected,link=self,width=500]
+
Click **Import pipeline**.

. The pipeline graph shows the 4 automated steps:
+
image::eval18.png[Pipeline definition graph showing setup-mlflow-op then create-dataset-op then run-simple-eval-op then report-results-op,link=self,width=700]
+
--
* **setup-mlflow-op**: Configure MLflow tracking URI, workspace, and experiment
* **create-dataset-op**: Create the evaluation dataset on the MLflow server (6 test cases covering common mortgage inquiries)
* **run-simple-eval-op**: Run the 3 deterministic scorers (contains_expected, has_numeric_result, and response_length)
* **report-results-op**: Print the evaluation summary
--

This evaluation is packaged as a pipeline that can run without a notebook: fully automated and reproducible.

== Exercise 2: Run the evaluation pipeline

. Click **Actions** > **Create run**:
+
image::eval19.png[Actions dropdown showing Create run and Create schedule options,link=self,width=300]
+
NOTE: Notice the **Create schedule** option. In production, you would schedule evaluations to run periodically (e.g., every 6 hours) to continuously monitor agent quality.

. In the **Create run** form, set the run name to `eval-run-1`:
+
image::eval20.png[Create run form showing run type project experiment and run name fields,link=self,width=700]

. Scroll down to **Parameters** and configure the required values:
+
--
* **mlflow_tracking_uri**: `{mlflow_tracking_uri}`
* **mlflow_workspace**: `{user_project}`
--
+
image::eval21.png[Create run Parameters section showing agent_name dataset_name mlflow_experiment_name mlflow_tracking_uri and mlflow_workspace,link=self,width=500]
+
The other parameters (`agent_name`, `dataset_name`, `mlflow_experiment_name`) use sensible defaults. Click **Create run**.

. The pipeline starts executing. You can watch each step complete in the graph view:
+
image::eval22.png[Pipeline run eval-run-1 executing showing the 4-step graph with Running status,link=self,width=700]
+
Each step runs in its own container on the OpenShift AI platform. The pipeline authenticates to MLflow using the pod's Kubernetes service account token, so no manual token management is needed.

== Exercise 3: View automated evaluation results in MLflow

. Switch to the MLflow UI. Make sure you are still in the **{user_project}** workspace:
+
image::reselect-project-mlflow.png[MLflow workspace selector showing user project workspace,link=self,width=400]
+
Once the pipeline completes, the evaluation results appear in MLflow.

[start=2]
. Navigate to the experiments tab to view the traces. The name of the new experiment is **multi-agent-loan-origination-eval**. 
+
image::find-new-exp.png[MLflow experiments tab showing multi-agent-loan-origination-eval experiment,link=self]
+

. Click on `Traces` from the side bar:
+
image::traces-nav.png[MLflow sidebar showing Traces navigation link,link=self]
+

You'll see the 6 new traces from the pipeline run with their assessment results:
+
image::eval23.png[MLflow Traces showing 6 automated evaluation traces with assessment columns,link=self,width=700]
+
The results show each trace with its scorer assessments, produced by an automated pipeline instead of a manual notebook run.

. To see all assessment and expectation columns, click **Columns** and check **All Assessments** and **All Expectations**:
+
image::eval24.png[MLflow Columns dropdown showing All Assessments and All Expectations checkboxes,link=self,width=250]

TIP: If assessment columns are not visible in the Traces view, use the **Columns** dropdown to enable **All Assessments**. MLflow doesn't always show them by default.
